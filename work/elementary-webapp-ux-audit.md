# 초등 교육용 웹앱 UX 감사

- 감사일: 2026-08-31
- 대상: `빈 공간 패스 전술판`
- 범위: Stage 0 이후 실제 브라우저 학습 흐름, 1280/375/320px 화면, 오답 회복, 근거 기록, 어린이용 문장, 완료 상태
- 제외: VoiceOver 구현·검증, 음성/TTS, 서버 저장, 새 시뮬레이션 엔진, 커밋·푸시·배포

## 기준선

Stage 0은 `ready`였다. Playwright 브라우저 증거, Impeccable 수동 검토, UI/디자인 시스템, 프론트엔드 구현 런타임이 확인되었다. 고정된 7×5 SVG 경기판과 여섯 미션의 DOM 흐름만으로 학습 목적을 확인할 수 있으므로 새 시뮬레이션은 `not-needed`로 판단한다.

브라우저에서 실제로 확인한 사실:

- 1280px 입구에서 `학습 시작하기`의 문서 위치가 첫 900px 뷰포트 아래였다.
- 375px 입구에서 시작 버튼이 약 1424px 지점에 있어 첫 화면에서 바로 시작할 수 없었다. 320px에서도 같은 현상이 반복됐다.
- 1280px 예측 오답 후 피드백이 늘어나면서 `다음 단계로`가 900px 뷰포트 아래로 내려갔다. 답변 후 자동으로 다음 행동을 찾을 수 없었다.
- 전체 여섯 미션을 완료해 `전술 기록`까지 도달했지만, 완료 화면에는 다음 학습 행동이나 짧은 회고 안내가 없었다.
- 미션 5 지원 근거를 선택하고도 결과 카드에 `기록한 근거 문장이 없어요.`가 표시되었다. 지원·이동 근거 옵션을 결과 집계가 읽지 못하는 데이터 연결 문제다.
- 이동 선택지, 수비 공개 문장, 일부 보고서가 `A2`, `c5r1`, `은(는)`, `검수된 계획(seq-left)` 같은 내부 표현을 어린 학습자에게 그대로 노출했다.
- 320/375px에서 가로 넘침은 없었으나, 보드 좌표·범례와 긴 선택지 때문에 핵심 판단보다 구현용 표기가 먼저 읽혔다.

## 수용 기준

- P0/P1 미해결 없음.
- 320px와 375px 첫 화면에서 시작 CTA가 보인다.
- 오답 예측 후 피드백과 `다음 단계로`가 같은 흐름 안에서 찾아진다.
- 이동·지원에서 선택한 근거가 보고서의 사용 근거에 남는다.
- 선택지·보고서의 주 문장이 역할·방향·공간 관계 중심으로 읽힌다.
- 여섯 미션을 끝까지 완료하고 takeaway, 인쇄 CTA, 개인정보 안내를 확인한다.
- 기존 reducer/evaluator 계약, 여섯 미션 ID, light mode, tab-memory, `gi-pulse` CTA를 유지한다.
- lint, typecheck, unit, a11y, release, line-count, build를 통과한다. E2E는 환경상 preview 포트 점유 여부를 별도로 기록한다.
